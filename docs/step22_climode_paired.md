# 22단계: ClimODE 공개 체크포인트와 best 모델(blend_band)의 짝 비교

소유자 요청(2026-10-28 05:43): "다시 ClimODE와 비교, 특히 ClimODE는 GPU로 학습한 제공된 그들의 모델 파라미터를 사용해서".
논문 표의 숫자(z500 193 / 479 / 784)가 아니라 저자들이 공개한 체크포인트 `ClimODE_global.pt`(2006~2016년 학습, GPU, 300 epoch)를
저자 코드(`third_party/climode`, 그대로)로 같은 초기장에서 돌려 짝지어 비교합니다. ClimODE는 추론만 하고 다시 학습하지 않습니다.

## 1. 방법

- ClimODE: `scripts/run_climode_eval.py`(11단계)로 체크포인트를 144 h까지 1 h Euler로 적분(저자 평가 설정: BatchNorm은 학습 모드, 두 시험 해를 한 batch로).
  CPU 4코어에서 IC 쌍(2017년 하나 + 2018년 하나)마다 약 18분이라 전체 180쌍 대신 두 부분집합을 씁니다.
  - **1월 16개**: 11단계에서 돌린 각 해의 첫 8개(`runs/step11/climode/climode_pred.npz`, 1월 1~15일).
  - **계절 18개**: 새로 추가한 `--ic-offset 10 --ic-stride 20`으로 각 해 9개(21, 61, 101, 141, 181, 221, 261, 301, 341일째: 1월 말부터 12월 초까지 40일 간격, `runs/step22/climode_spread`).
  - 둘을 합친 **34개**가 본 결과이고(`scripts/merge_climode_pred.py`), 1월만의 결과는 계절 편향을 보려고 따로 둡니다.
- 우리 쪽: 저장된 앙상블(`<arm>_ens_<해>.npz`)에서 정확히 같은 IC를 꺼내 ClimODE 점수 함수(`run_step11_climode.py`: RMSE, ACC, Gaussian CRPS)로 채점하고,
  팔 − ClimODE의 짝 차이에 IC 부트스트랩 95 % 구간을 붙입니다(`scripts/compare_step13_climode.py`). 앙상블에는 멤버 CRPS(`crps_ens`)도 함께 둡니다.
- 팔: **blend_band**(20단계 best: μ* = a + b·G(x) 코어 + c·회귀 + d·x(t), FM·PINN 편차, 대역 Γ), 대조군 blend_lp0_band(데이터만의 코어로 같은 혼합),
  regm_band(13단계 보고 모델), 회귀 앙상블, 그리고 단일 결정론 모델끼리 비교하려고 G(x) 코어 단독(`dyn_gfeat`).
- 학습 자료는 모두 CPU 4년(2012~2015)입니다. `run_step13_best.sh CLIMODE=1`이 같은 절차를 돌리며(`CLIMODE_ICS`, `CLIMODE_STRIDE`, `CLIMODE_OFFSET`;
  GPU에서는 `CLIMODE_ICS=180`으로 전체), `BLEND=1`이면 blend_band와 코어도 짝 채점에 들어갑니다.

읽기:

1. **z500과 t2m은 모든 lead에서 blend_band가 체크포인트보다 좋고 구간이 0을 넘지 않습니다.** 24 h에서 −35(15 %), 144 h에서 −164(18 %).
   ClimODE의 t2m은 지속성보다 나쁜데(11단계와 같음) 이건 체크포인트의 알려진 약점입니다.
2. **24 h의 t850·u10·v10은 ClimODE가 좋습니다**(t850 +0.22 K, 바람 +0.3~0.4 m/s). ClimODE의 수송(이류) 구조가 짧은 lead의 바람과 하층 온도에서 강한 자리이고,
   우리 평균은 6 h 증분 24개를 한 번에 내는 시퀀스 회귀 + 코어라 첫 하루의 바람이 거칩니다. 72 h에서 같아지고 144 h에서는 다섯 변수 모두 우리가 좋습니다.
3. **단일 모델끼리**(G(x) 코어 단독 대 ClimODE)는 24~72 h에서 코어가 좋고(−28, −45) 144 h에서 같습니다(−12 [−69, +50]). 즉 "ClimODE를 이긴다"의 본체는
   lead별 두 모델 혼합 + FM 편차이고, 코어 하나는 ClimODE와 같은 급입니다(20단계의 판독과 같음).
4. **대조군**(데이터만의 코어 혼합)도 ClimODE를 같은 폭으로 이깁니다(z500 −17 / −62 / −169). 24 h의 −35 대 −17이 G(x) 특징의 몫이고, 144 h에서는 반대입니다.
5. ClimODE의 σ는 lead에 따라 톱니처럼 오르내립니다(z500 퍼짐 195, 45, 175, 61, 186, 81). 체크포인트 자체의 성질이라 그대로 둡니다. 우리 퍼짐은 오차와 같이 자랍니다.

## 4. 약점

1. **IC 수**: 34개(1월 16 + 계절 18)이지 ClimODE 프로토콜의 360개가 아닙니다. 부트스트랩 구간은 이 34개 안의 변동만 봅니다. GPU에서는 `CLIMODE=1 CLIMODE_ICS=180`으로 전체를 돌릴 수 있습니다.
2. **ClimODE 쪽 조건**: 저자 평가 코드 그대로(BatchNorm 학습 모드, 두 시험 해 한 batch). 11단계에서 평가 모드로 바꾸면 24 h z500이 200 → 250으로 나빠졌으니 이 설정이 ClimODE에 유리한 쪽입니다.
   자료는 WeatherBench2의 보존 재격자(64×32)이고 저자들은 WeatherBench1 5.625° 파일로 학습했습니다. 같은 ERA5지만 재격자가 달라 1월 16개의 24 h 235가 논문 193보다 큰 데 일부는 자료 차이, 일부는 1월(겨울) 편향입니다.
3. **같은 조건이 아닙니다**: ClimODE는 2006~2016년 11년을 GPU에서 300 epoch 학습한 단일 결정론 모델 + Gaussian σ이고, blend_band는 2012~2015년 4년을 CPU에서 학습한 두 모델의 lead별 혼합 + 8멤버 앙상블입니다.
   학습 자료가 적은 쪽이 이겼으니 자료 차이는 우리에게 불리한 방향이지만, 모델 수와 보정(2016년 닫힌 형 계수)은 우리에게 유리한 방향입니다. 단일 모델 비교는 3번 항목의 코어 단독입니다.
4. **CRPS의 정의가 다릅니다**: ClimODE는 자신의 σ로 Gaussian CRPS, 우리는 멤버 std의 Gaussian CRPS와 멤버 CRPS 둘 다입니다. 표는 둘 다 적었고 결론은 같습니다.
5. 1월 16개는 겨울만이라 z500 오차가 연평균보다 큽니다(우리도 360개 평균 188 / 451 / 723 대 1월 200 / 461 / 746). 계절 18개가 이 편향을 가립니다.
