# 19단계: 13단계 멤버의 출력단 super-resolution (5.625° → 2.8125°)

소유자(2026-10-28 00:02): "그럼 반대로 13단계에서는 SR을 쓸만한가요?" 00:03: "특히 SR또한 pre train 시켜서 고해상도를 낼수 있도록 지속적으로 해보면?"

## 요청을 이렇게 읽었습니다

18단계에서 SR은 물리 연산자 앞단에서 쓸모가 없었습니다(보간이 실제 2.8° 자료와 같은 상관). 남은 자리는 **보정된 멤버 뒤의 출력단**입니다: 5.625° 멤버 → 2.8° 산출물. 거기서 SR은 역학을 건드리지 않고 "보간이 잃는 세부"만 더하므로, 이득은 보간 간극(18단계 표: z 3 %, t 6 %, u/v/q 19~20 %)에 갇혀 있고 **2.8° 채점에서만** 보입니다. 5.625° 채점(ClimODE 비교)은 바뀌지 않습니다. "pre train"은 ERA5 (5.625°, 2.8°) 분석장 쌍으로 SR을 먼저 학습해 두고 멤버마다 적용하는 것으로 읽었습니다.

## 1. 구현 (기존 코드 재사용 + 논문 구조의 축소판)

- 자료: WB2 2.8125°(128×64)에서 ClimODE 채점 5변수(z500, t850, t2m, u10, v10) 2012~2018을 ClimODE 형식으로 추출(`scripts/wb2_to_kai.py --grid 128x64 --climode-only`, 1.6 GB). 5.625° 쪽은 11단계의 `era5_data`.
- 모델 `pgcfm/sr.py` SRNet (Chiang et al. 2024, arXiv 2403.17847의 축소판, 14만 파라미터): cascaded conv(편향 보정) → CBAM 잔차 주의 블록 4개 → skip 결합(1×1) → pixel shuffle ×2 → 2.8° 지형·육지비율·위도를 결합하는 머리 → **보간 + 보정**(전역 잔차: 18단계의 FFT 경도 + 3차 스플라인 위도 보간이 바탕). 패딩은 ClimODE 방식(위도 반사, 경도 순환). 입력은 5.625° 5변수 + 5.625° 정적장, 출력은 2.8° 5변수.
- 학습 `scripts/run_step19_sr.py`: 2012~2015 6시간 분석장 쌍 5844개, 배치 16, 3000 반복, 위도 가중 MSE(변수별 z-score), 2016으로 검증(SR/보간 RMSE 비 평균이 최소인 반복 저장). 31분(2 threads).
- 평가(2017~2018): (a) 분석장 SR: 5.625° 분석장을 SR한 것 대 보간, 2.8° 분석장 기준 RMSE. (b) 앙상블: 13단계 보고 모델 `regm_sband_clim_flow`의 멤버(ClimODE IC 360개 × 8 멤버 × 6 리드, 5.625°)를 **멤버마다** 보간/SR → 2.8° 진실로 앙상블 평균 RMSE, 퍼짐, CRPS(ClimODE 정규화, properscoring). 지속 = x₀ 보간. 같은 멤버의 5.625° 채점을 참고선으로.

실행: `bash scripts/run_step19_queue.sh` (결과 `runs/step19/sr.json`, 그림 `docs/step19/fig_sr_sr.png`).

### 2.3 판독

1. **지면 온도에서는 쓸 만합니다.** 2.8° 채점에서 t2m RMSE −10 %(24 h), −3 %(144 h), CRPS −8 % → −3 %. 분석장에서 되찾은 1/3이 예보 멤버에도 거의 그대로 옮겨집니다. 이유는 그 세부가 **정적**(지형·해안 대비)이라 예보 상태가 틀려도 보정이 유효하기 때문입니다.
2. **바람은 분석장에서는 38 %를 되찾지만 예보 멤버에서는 0입니다.** u10 RMSE 2.52 → 2.51 (24 h), 144 h에는 +0.7 % 악화. 바람의 세부는 흐름 의존적이라 5.625° 예보 상태의 오차(2.1 m/s, 보간 간극 1.2 m/s의 2배)가 있으면 SR이 더한 세부가 맞는 자리에 놓이지 않습니다. 퍼짐은 2.19 → 2.48로 커져 SSR은 좋아지지만(0.87 → 0.99) CRPS는 그대로입니다: **SR이 더한 세부는 멤버 사이의 불일치로만 남고 오차를 줄이지 않습니다.**
3. **z500·t850은 변화 없음**(±0.1 %). 보간 간극이 예보 오차의 1/5~1/3이고 SR이 그중 10 %만 되찾아 제곱합에서 사라집니다.
4. **2.8° 채점은 5.625° 채점보다 항상 나쁩니다**(t2m 24 h: 1.70 대 1.42). 진실의 분산이 더 크기 때문이며, SR은 그 격차의 1/3~1/2를 메웁니다(t2m: 0.46 K 격차 중 0.18 K).
5. "**지속적으로**"(더 높은 해상도로) 가려면 단계마다 그 해상도의 진실(WB2 1.4°, 0.25°)과 4배 비용이 들고, 되찾는 몫은 정적 세부(t2m)에서만 유지될 것입니다. 바람·기압계의 세부를 2.8°에서 맞히려면 SR이 아니라 **예보 자체의 2.8° 오차**가 줄어야 합니다(18단계 결론과 같음).

### 2.4 결정

- 13단계 산출물에 **t2m(과 지면 변수의 정적 세부)을 위한 SR 출력단**은 붙일 가치가 있습니다: 비용 31분 학습 + 멤버당 밀리초, 2.8° t2m −3~−10 %. z500/t850/바람에는 붙이지 않습니다(이득 0, 바람은 퍼짐만 부풀림).
- 결정론적 SR은 조건부 평균이라 멤버에 같은 세부를 더합니다(바람 퍼짐 증가는 이 세부가 멤버마다 달라진 결과). 확률적 SR(조건부 flow matching, 기존 `pgcfm.cfm`)은 바람의 작은 규모 불확실성을 멤버 안에 넣을 수 있지만, CRPS를 줄이려면 세부가 맞아야 하므로 2.8° 예보 오차가 먼저 줄어야 합니다. 이 단계에서는 만들지 않습니다.

## 3. 약점

1. 학습 3000 반복, hidden 32, 블록 4, 씨앗 1. 검증 비가 0.76에서 평평해져(2500~3000 반복) 용량이 더 있으면 지면 변수에서 몇 % 더 되찾을 수 있습니다. 논문의 CBAM·pixel shuffle은 썼지만 shrinkage·fusion의 세부 형태는 단순화했습니다.
2. 입력은 채점 5변수뿐입니다(13단계 멤버 npz가 5변수만 저장). 66채널 상태를 입력으로 주면 바람의 세부(상층 바람·기압)가 더 들어오지만, 멤버 npz를 다시 만들어야 합니다(샘플링 55분/년 + 보정 23분).
3. 2.8° 진실은 WB2의 보존 재격자(0.25° 상자 평균)라 "진짜 2.8° 세부"보다 매끈합니다. 되찾은 몫은 그 기준에 대한 값입니다.
4. 앙상블 CRPS는 ClimODE 정규화 눈금(5.625° 2006~2018 최소·최대)으로 2.8°에서도 같은 눈금을 썼습니다. 변수 사이 비교가 아니라 보간 대 SR 비교만 뜻이 있습니다.
5. 지속(x₀ 보간)은 2.8°에서 SR하지 않았습니다(SR한 지속은 멤버 보간과 같은 이유로 t2m에서 더 좋아질 것).

## 4. GPU에서 실행하기 (2026-10-28 추가)

소유자 요청(02:46): "앞으로 GPU로도 SR을 연산할 수 있으니 그 기능도 실험할 수 있도록". 같은 스크립트에 다음을 넣었습니다(CPU 결과는 그대로).

- `run_step19_sr.py --device auto|cuda|cpu`, `--amp`(bf16 학습), `--train-range 1979 2015`(연도 범위), `--chunk`(GPU면 30). 학습 자료는 호스트 메모리(37년 6.6 GB), 망·보간 행렬·채점은 장치 위.
- `--ens` 에 arm 여러 개: `sr.json`의 `evaluation.ensemble[arm][해]`, 그림 `fig_sr_sr_<arm>.png`. `--eval-only` 로 학습한 망에 새 arm만 채점.
- `--save-sr`: SR한 멤버를 `<out>/<arm>_sr_<해>.npz`(float16, `E_sr` (IC, 멤버, lead, 5, 64, 128), `ics`, `leads`, `lat`)로 저장. 2.8° 산출물을 다른 채점이나 그림에 쓸 때.
- CRPS는 properscoring의 추정량을 torch로 옮겨 장치에서 계산(무작위 자료에서 차이 7e-7).
- `scripts/run_step13_best.sh`의 `SR=1` 단계: 2.8125° 진실 내려받기(`SR_TRAIN_YEARS`, 기본 = 학습 연수) → SR 학습(`SR_ITERS`, `SR_BATCH`; broad 기본 20000 × 32) → 채점된 arm 전부 채점(`SR_CHUNK`), `SR_SAVE=1`이면 멤버 저장. 명령과 결과 읽는 법은 `docs/RUN_ON_GPU.md` 12절.
- 스모크(CPU, 이 세션): 기존 `runs/step19/sr.pt`로 두 arm × 2 IC 채점 + 저장, 1년 × 3 반복 학습 경로, 분석장 수치는 2.1절과 같음.
